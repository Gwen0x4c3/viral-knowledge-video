# Script writing: angle, hook, structure, density

The script decides 70% of how good the video is. Visuals can't rescue a boring script.

## 0. What actually keeps people watching

Accurate facts are the floor, not the goal. People finish a video because of a **story engine**:

1. **One central question** (an open loop) that is raised in the first seconds and answered only near the end:
   "穿着刀枪不入的盔甲，骑士为什么会消失？" Every beat is a step toward the answer; never fully close the loop early.
2. **A protagonist with stakes** whenever the material has one (a person, a group, even an object): someone wants
   something, faces obstacles, wins or loses. Facts become episodes in their life instead of a list.
3. **Escalation**: each beat raises the stakes or the surprise. The best beat goes last, not first.
4. **Concrete, sensory details** over abstract facts: "一顶头盔的价钱 = 一头牛" beats "盔甲很贵"; "穿着盔甲翻跟头" beats "盔甲不重".
5. **A bridge to the viewer's world**: start from what *this* audience already "knows" (for Chinese viewers: 游戏《骑马与砍杀》,
   《权力的游戏》, 武侠, 中国历史的对应物, 日常生活), then subvert or deepen it.
6. **Social currency**: one line the viewer will repeat to friends ("骑士不是被火枪打败的，是被账本打败的").

Information density serves the engine. Sixteen facts with no engine is a list nobody finishes.

## 1. From topic to angle

A **topic** is a noun ("骑士", "蜂蜜", "罗马帝国"). An **angle** is a question or claim with tension. Generate many
angles, then choose by the pitch process in §1c, not by habit.

| Angle type | Pattern | Example |
|---|---|---|
| Mystery / why | X为什么会Y？ | 刀枪不入的骑士，为什么会消失？ |
| Protagonist arc | 一个人从A到B | 没继承权的穷小子，靠"抓人换钱"当上英格兰摄政 |
| Myth-busting | 你以为X？其实Y | 盔甲重到要吊车吊上马？ |
| Hidden cost / money lens | X到底多少钱？ | 养一个骑士，要多少头牛？ |
| Shocking number | 一个数字颠覆认知 | 西部5大牛镇15年只有45起凶杀 |
| Day-in-the-life / POV | 如果你是X | 假如你是13世纪的骑士，你的一天 |
| Comparison | X vs Y | 欧洲骑士 vs 宋朝重骑兵 (only with solid sources) |
| Rise and fall | 从巅峰到消失 | 牛仔黄金时代只持续了20年 |
| Countdown / list | N个… | (only when §3F applies) |

## 1b. Choose the MODE first (before pitching) — it changes every rule below

| Mode | Topic examples | Goal | Length | What dominates |
|---|---|---|---|---|
| **Story** | cowboys, knights, pyramids, a historical figure, an event | curiosity + emotion | 60–90 s | an open question or a protagonist, escalating beats, vivid details |
| **Concept explainer** | an algorithm (Raft, PageRank), a science mechanism (vaccines, black holes), how a system works (DNS, the stock market), an economic idea | the viewer **understands** and could explain it to a friend | 90–150 s (Douyin/Bilibili accept this for good explainers) | definitions, one running example, cause → effect |

Ask: "after watching, does the viewer need to *know* things or *understand how* something works?" If the latter, use
**explainer mode** (section 10). A trivia-style script for a concept produces a video that sounds smart and teaches
nothing. A real failure: a Raft video whose subtitles were all short punchy fragments ("心跳一断，随机闹钟开始倒数",
"账本不够新的，没资格当领导") left viewers unable to say what Raft actually is.

## 1c. Pitch three, then choose (mandatory)

Write **3 pitches that use different structures from §3** (e.g. a mystery, a protagonist arc, a POV). Each pitch has a
title, a hook line, the central question, 4–6 beats, the twist/payoff and the line viewers will repeat. Score each 1–5:

| Criterion | Question |
|---|---|
| Engine | Is there one open question or a protagonist with stakes that runs through the whole video? |
| Escalation | Does each beat raise the stakes, with the best beat last? |
| Bridge | Does it start from something this audience already knows or cares about? |
| Material fit | Do the strongest verified facts and visuals fall naturally into this structure? |
| Freshness | Is it different from the last videos made with this skill (structure, hook pattern, ending)? |
| Load | Can a viewer follow it with ≤ 1 new proper noun per ~8 s? |

Pick the highest total and write the scores in the brief. A numbered list ("N个真相") almost never wins the Engine
criterion. Choose it only when §3F applies.

## 2. The hook (first 3 seconds, 1–3 lines)

The hook opens the central question with an image the viewer can see immediately. Patterns (vary them between videos):
- **In medias res**: drop into a vivid moment. `1170年，一个骑士在比武场上被打翻在地，对手不杀他，只要他的马和盔甲。`
- **Paradox**: `穿着刀枪不入的盔甲，骑士却在几百年里消失得干干净净。`
- **Bridge + twist**: `在《骑马与砍杀》里，你一个骑士能冲垮一整队步兵。可历史上，骑士最怕的不是长枪，是账单。`
- **Stakes question**: `一个没有继承权的穷小子，怎么当上了英格兰的摄政？`
- **Impossible-sounding fact**: `穿着二十多公斤的全身盔甲，骑士能翻跟头。`
- **Direct contradiction** (sparingly): `金字塔不是奴隶建的。`

**Worn-out 营销号 formulas.** Chinese viewers recognize these instantly as low-effort templates. Don't use them as the
backbone, and never reuse one across consecutive videos:
- `你以为…？错！` + record scratch (fine once in a while as a beat, not as the default opener)
- `今天N个真相，最后一个最扎心` / `看完你就懂了` / `一定要看到最后`
- a generic `评论区聊聊` / `你怎么看？` with no specific question
- "N个真相" chapter cards for material that is really one story

Never open with greetings, a channel intro, "今天我们来聊聊", a definition, or a date alone.

## 3. Structures: choose by the material, not by habit

**A. Mystery / investigation**: *use when the topic has a "why/how did this happen" question.*
Hook (the puzzle) → suspect 1 tested and rejected (with evidence) → suspect 2 rejected → a clue that points elsewhere →
the real answer → what it means today. Myth-busting facts become *evidence*, so the list turns into a plot.
Example: 骑士为什么消失？ 火枪? (共存300多年，盔甲反而加厚防弹) → 太重? (20–25公斤，能翻跟头) → 线索：一顶头盔=一头牛 → 答案：养不起，雇步兵更便宜。

**B. Protagonist arc**: *use when a vivid, well-documented person (or group) embodies the topic.*
Who they were and what they lacked → what they wanted → the obstacle → the clever/brutal method → the rise or the fall →
the lesson about the larger topic. Example: 威廉·马歇尔 (没有继承权 → 比武是合法"抢劫"生意，教会禁了也挡不住 → 自称抓了500多个骑士换赎金 → 当上英格兰摄政).

**C. Timeline rise and fall**: *use for eras, empires, companies, technologies.* Open with the ending or the peak, go back
to the humble origin, rise (numbers growing), peak, the cause of the fall, what remains today.

**D. Comparison / versus**: *use when two things the audience knows are secretly similar or different.* Hook (vs) →
round 1 → round 2 → round 3 → surprising winner → why it matters. Needs strong sources on both sides.

**E. POV / day-in-the-life**: *use when daily details are the interesting part* (food, sleep, money, danger, hygiene).
"如果你是X" → morning → work → danger → money → night → the twist about how it ended.

**F. Numbered list**: *use only when the facts are truly independent, each is strong on its own, and you can order them
by escalation.* Even then, connect the items with one question ("哪个才是骑士真正的死因？") so the viewer has a reason
to stay until the last one. Avoid the "真相①②③④" chapter-card look if the previous video used it.

For every structure, plan an **emotional curve** (curiosity → surprise → amusement → tension/sadness → reflection → payoff).
The music follows it (see audio.md), so write it down.

## 4. The ending (last 8–12 s)

1. **Twist or callback.** Bring back the hook image with new meaning. Cowboy: the 1903 gun shot shown in the hook comes
   back as `一枪对着观众，打了整整一百年` (*real* cowboys vanished just as the *movie* cowboy was born).
2. **A specific comment question** tied to the content (a choice, a prediction or a personal angle), e.g.
   `如果你生在中世纪，你愿意当骑士，还是当那个比他便宜十倍的长枪兵？` Avoid a bare `评论区聊聊` / `你怎么看`.
3. **Closing visual** (no speech, ~2 s): a quote line like `真正的西部，比电影更精彩`, fading out with the music resolving.

## 5. Density rules (story mode — explainer mode: see section 10)

- **Cognitive load:** at most ~1 new proper noun (person, place, foreign term, year) every 8 s. Every name must either
  come back later or be the protagonist. Foreign names get a Chinese anchor ("英国最有名的骑士 威廉·马歇尔"). Drop
  etymologies of foreign words unless the whole video is about language.
- Prefer 1 vivid detail the viewer can picture over 3 abstract facts. Convert numbers into relatable units when the
  source supports it (一顶头盔 = 一头牛; 20–25公斤 ≈ 一袋大米多一点).
- 70–90 s ≈ 18–24 lines ≈ 300–380 Chinese characters (edge-tts at +18–24% speaks ~5.0–5.4 chars/s, plus pauses).
  Leave air: about 0.15 s between lines and 0.5–0.9 s before sections and big reveals (`GAP`/`PRE`). A wall of
  non-stop speech feels rushed (急促) however good the edit is.
- **One concrete fact every 5–7 seconds.** Facts are numbers, names, dates, places, causes, quantities.
- Kill these line types: meta-talk ("接下来让我们看看", "这个问题很有意思"), vague adjectives ("非常厉害"),
  repetition of the previous line, morals that aren't earned.
- **Logical connectives are NOT filler**: 因为 / 所以 / 但是 / 于是 / 如果…就 / 为了 / 也就是说 carry the reasoning.
  Keep them. Full sentences with an explicit subject (谁 做了 什么) beat telegraph fragments.
- Replace adjectives with numbers: ✗ `牛仔工资很低` → ✓ `月薪只有25到40美元`.
  ✗ `路程很远` → ✓ `一走就是一千多英里`.
- Story mode: each line ≤ 30 characters; short punchy lines (`进城，先交枪！`) are gold. Explainer mode: lines may be up to
  ~40 characters when a clause needs its subject and reason. Subtitles split on punctuation anyway, so clarity beats brevity.

## 6. Writing for TTS and subtitles

- The `text` is both spoken and displayed. Punctuation (，。！？：、) splits subtitle phrases, so put a comma every
  4–10 characters, at natural breath points.
- Numbers as digits: `1886年`, `3000多个`, `25到40美元`. The voice reads them correctly and digits look punchy on screen.
- English words: avoid them when a Chinese name exists (say `火车大劫案`, show "The Great Train Robbery" as a label;
  transliterate people: `巴斯·里夫斯`). Technical names that have no Chinese form (Raft, Paxos, etcd, K8s, TiKV) are
  unavoidable — handle them deliberately:
  - Keep the display spelling in `text`, and add a pronunciation in `SAY` (script_data.py), e.g.
    `SAY = {"etcd": "E T C D", "K8s": "K8S", "TiKV": "T i K V", "Raft": "Raft"}`. The voice reads the SAY form;
    subtitles still show the real spelling and stay in sync.
  - Introduce the term with a Chinese descriptor the first time: `分布式数据库 TiKV`, `容器平台 Kubernetes`, so a
    mispronunciation doesn't cost understanding.
  - After TTS, check those lines in the Whisper transcript (`check_audio.py --whisper`). If a term is heard as something
    else ("etcd" → "At"), adjust SAY (spell letters with spaces, use uppercase) and re-run tts for that line only.
- Avoid ambiguous polyphones in key words when possible (e.g. 行 háng/xíng). If one is mispronounced, rephrase.
- Use `！` and `？` honestly: they change the delivery a bit, and rate/pitch per line does the rest:

| Line role | rate | pitch |
|---|---|---|
| Hook question | +14~18% | +6Hz |
| Reversal ("错！") | +14~16% | +8~10Hz |
| Chapter claim ("真相一：…") | +14~18% | +6Hz |
| Evidence / explanation | +18~24% (never above +26%) | 0~+2Hz |
| Emotional / sad line | +0~8% | -2~-6Hz |
| Ending question | +10~14% | +4Hz |

## 7. Highlights

Per line 1–3 keywords: `y` for names, places and objects; `r` for shocking or negative words (错, 少得可怜, 消失);
`big` for the single punchline of a beat (≤ 1 per ~10 s; e.g. 错, 3000, 穷打工仔, 一百年). If a graphic already shows the
number in huge type, put it in `BIG_SKIP` so it doesn't appear twice.

## 8. Fact discipline

- Prefer facts that appear in multiple reputable sources (encyclopedias, museum sites, academic summaries).
  If you have web access, verify each number. If you don't, use only facts you are highly confident in, and keep the
  rest qualitative.
- Contested claims get hedges: `传说` (legend has it), `有人认为` (some think), `据估计` (it's estimated), `约` (about). Estimates get ranges or "about".
- Don't invent precise figures, quotes or dates to sound authoritative.
- Write a short "facts used + confidence" list and include it in your final report to the user.

## 9. Worked example (cowboy, annotated): one example of structure F, NOT a template

Don't copy its hook, its "N个真相" frame or its ending into other topics. It shows line-level craft (concrete numbers,
rate/pitch variety, callback ending). Its structure was a list, which is the weakest engine (see §0 and §1c).

The original cowboy video used +24~28% on explanation lines; viewers found the result slightly rushed, so use the calmer
rates in the table above.

```
L01 你以为的牛仔，是这样的？                       hook: familiar picture
L02 白人硬汉，牛仔帽一戴，天天拔枪决斗。             the cliché in 3 images
L03 错！好莱坞骗了你整整一百年！                   snap reversal + stakes
L04 今天四个真相，最后一个最扎心。                 promise + cliffhanger

L08 真相二：每四个牛仔里，就有一个是黑人！           claim with a ratio
L09 南北战争后，大批自由黑人，涌进了德州牧场。        cause
L10 黑人警长巴斯·里夫斯，一生抓了3000多个罪犯，传说他就是独行侠的原型。 person + number + hedged legend

L12 堪萨斯五大牛镇，15年里，凶杀案加起来才45起。     the shocking number
L13 很多小镇规定：进城，先交枪！                    vivid detail
L14 最扎心的真相四：牛仔，其实就是一群穷打工仔！       emotional turn
L15 很多人才十几岁，月薪只有25到40美元。             numbers instead of adjectives
L16 十几个人赶三千头牛，一走就是一千多英里。          numbers
L17 晚上还得轮流给牛唱歌，防止牛群受惊炸群！          surprising human detail
```

Consistency check that caught a real bug: the hook promised "三个真相" but the script had four, so it was fixed to "四个".
Re-read the hook after finishing the body.


## 10. Explainer mode (algorithms, science, systems, economics)

### 10.1 Before writing: learning objectives
Write the **3 sentences a viewer should be able to say after watching**, in plain words. For Raft:
1. 几台机器要存同一份数据，Raft 的办法是：选出一个领导，所有修改都先交给领导，再由它同步给其他机器。
2. 领导定时发心跳；心跳断了，别的机器等一个随机时间后站出来竞选，拿到过半票的成为新领导。
3. 一条修改只有被过半机器记下才算数；因为任意两个"过半"一定有重叠，所以新领导总能拿到它，数据不会丢。
Every line of the script must serve one of these objectives (or the hook/ending). Cut anything that doesn't, even true and
interesting facts (user studies, author anecdotes). Those go in at most one line of context.

### 10.2 Time budget
| Part | Share | Content |
|---|---|---|
| Hook + the problem in everyday words | 15% | a concrete situation the viewer knows ("网盘服务器烧了，照片还在吗？") and *why it's hard* |
| Minimal context | ≤ 10% | who made it and why, one or two lines |
| **Core mechanism** | **60–65%** | each step = **what happens → why it's needed (what goes wrong without it)**, walked through ONE running example |
| Recap + significance + ending | 10–15% | the objectives restated in one breath, where it's used today, comment prompt |

### 10.3 Comprehension rules
- **Define every term at first use**, in one plain sentence, *before* using it: "领导（leader）：唯一负责接收修改的那台机器".
  Never use a term only once; if it isn't worth defining, don't name it.
- **One analogy system, mapped explicitly and kept consistent**: e.g. "5个人记同一本账 = 5台服务器存同一份数据", and say the
  mapping out loud once. Don't mix metaphors (老大 / 领导 / 班长 for the same thing).
- **One running example** carried through every step: 5 servers named A–E, A is leader, A crashes, C wins, a write "x=5"
  gets replicated. Each step changes the example's state, and the visuals (`g_nodes`) show exactly that state.
- **Every mechanism gets its "why"**: "随机等待时间 → 为了避免大家同时竞选、把票分散". A mechanism without a reason is just trivia.
- **Explicit subjects and causality**: "领导每隔一小会儿给所有人发心跳" ✓ / "心跳一断" ✗ (whose heartbeat?).
- **Numbers serve understanding**: "5台里坏2台照样能用" (a consequence the viewer can picture) beats "150到300毫秒" (detail).
  Keep detail numbers only if you explain them.
- **Recap before the ending**: restate the 2–3 objectives in one or two lines.
- It's fine to simplify (mark it: "简单来说"), but never say something false. If a detail is subtle (Raft's commit rule
  for entries from older terms), leave it out rather than state it wrongly.

### 10.4 Gate: the subtitle-only comprehension test (mandatory in explainer mode)
After writing script_data.py, read ONLY the line texts (no visuals) and write the 3-sentence explanation a viewer could
give. Compare it with your objectives. If you can't reconstruct an objective from the lines alone, the script is missing a
definition, a "why", or a step. Fix the script; visuals must not carry information the narration skips.
Stronger version: give the line texts to a fresh sub-agent with no context and ask "用三句话解释这个视频讲的东西是什么、怎么运作".

### 10.5 Bad → good (Raft)
| Bad (real failed script) | Problem | Good |
|---|---|---|
| 因为机房深处，每天都在选老大。 | metaphor with no mapping; "老大" never defined | 秘密在于：数据同时存在好几台机器上，而这些机器会选出一个"领导"，由它统一指挥。 |
| 几十台机器，怎么对同一本账达成一致？ | "账" undefined | 每台机器都有一本"账本"，按顺序记下每一次修改。难点是：怎么保证几台机器的账本一模一样？ |
| 心跳一断，随机闹钟开始倒数。 | no subjects, no why | 领导每隔一小会儿给大家发一次"心跳"，表示自己还活着。每个跟随者都有一个倒计时，收到心跳就重置。 |
| 150到300毫秒没动静，直接竞选！ | detail without purpose | 如果领导宕机、心跳停了，谁的倒计时先到，谁就站出来竞选。倒计时长短是随机的，就是为了避免大家同时竞选、把票分散。 |
| 过半确认才生效，领导挂了账也不丢。 | claim without reason | 一条修改要被过半机器记下才算数。为什么是过半？因为任意两个"过半"一定有重叠，新领导里总有人记得它。 |
| 账本不够新的，没资格当领导。 | rule without reason | 投票时，大家只投给账本至少和自己一样新的候选人，这样选出来的领导，一定拥有所有已经算数的修改。 |
